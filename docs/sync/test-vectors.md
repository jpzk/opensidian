# Opensidian Sync — test-vector format (M0, draft v1)

Goal: vectors that any implementation (ours now, an external reviewer's
later) can run with nothing but a hex decoder. Plain text, no JSON
parser needed, parsed with std only.

## Location

`crates/sync-proto/vectors/<area>.vec` (+ `crates/sync-crypto/vectors/`
for primitive KATs and imported Wycheproof sets in M2).

M2 primitive KATs (present, run by `crates/sync-crypto/tests/fips_kat.rs`
against the FIPS module and, for HMAC/HKDF, the reference provider):
`aes-gcm.vec` (GCM spec test cases 13–16 + tamper cases), `hmac-sha256.vec`
(RFC 4231), `hkdf-sha256.vec` (RFC 5869), `ed25519.vec` (RFC 8032 §7.1
TEST 1-3 + two flipped-bit negatives; suite v1 signatures, run by
`tests/fips_kat.rs::ed25519_rfc8032_known_answers`). Wycheproof (unmodified upstream
JSON, `vectors/wycheproof/`, run by `tests/wycheproof.rs`): AES-GCM
(256-bit key / 96-bit IV / 128-bit tag groups), ECDSA P-256 SHA-256 P1363,
HMAC-SHA256, HKDF-SHA256.

M2b container KAT (present, run by `crates/sync-core/tests/container_kat.rs`):
`crates/sync-core/vectors/container.vec` — suite 0x02 batch containers
(raw + zstd) produced once on the former AWS-LC FIPS module with module
nonces; the format is unchanged, they open through the OpenSSL provider. They are
OPEN-direction vectors: a reader must open the bytes to exactly `body`; the
header commitment is recomputed with the reference provider, and every
single-byte flip must be rejected. No nonce-injection hook exists (the
release provider cannot take a caller nonce), so seal-direction container
vectors with suite 0xf0 stay unimplemented; seal correctness is covered by
round-trip + rejection tests in `crates/sync-core/tests/object.rs`.

Areas: `padme`, `canonical`, `header`, `aad`, `objkey`, `commit`,
`words`, `keytree`, `batch`, `cfg`, `envelope`, `destroy-msg`.

## Grammar

```
file     = header *case
header   = "# " text LF          ; free comment lines
           "format = osy-vec-1" LF
           "area = " name LF
           "suite = " hex2 LF     ; 01 / 02 / f0..ff
case     = LF "[" case-id "]" LF *field
field    = key " = " value LF
value    = hex | decimal | "\"" utf8 "\""  | "valid" | "invalid"
```

- keys are lowercase `[a-z0-9_]+`; a case ends at the next `[` or EOF
- every case has `result = valid|invalid`; invalid cases also have
  `reason = "<short>"` (e.g. `"truncated"`, `"nonzero padding"`,
  `"unknown suite"`, `"commit mismatch"`)
- `comment = "…"` optional; `flags = a,b` optional (Wycheproof-style)
- hex values: lowercase, even length, no `0x`, may be empty

## Example

```
# Padme lengths
format = osy-vec-1
area = padme
suite = 01

[padme-1]
len = 100
padded = 104
result = valid

[objkey-commit-1]
k_obj = 000102…1f
vault_id = 00112233445566778899aabbccddeeff
obj_id = ffeeddccbbaa99887766554433221100
k_enc = …
commit = …
result = valid
```

## Determinism

Randomness (nonces, ids) is an INPUT field in vectors (`nonce = …`).
Implementations expose a test-only hook that injects it; release builds
use RandomizedNonceKey and cannot take a caller nonce (suite 0xf0 marks
vectors made with the hook).

## Rules

- vector files are generated by the reference implementation and
  reviewed; never edited by hand except to add invalid cases
- each file has a `sha256` line in `vectors/SHA256SUMS`; tests check it
- a change to a valid vector = a format break → bump the version axis
  (spec.md §1)
